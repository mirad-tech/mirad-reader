# 阅读玻璃与统一外观

下文主体保留 1.0.17（versionCode 18）的统一外观与阅读 GPU 方案，以及截至 2026-10-24 的历史证据。当前控制语义与限制以下列更新和[1.3.2 版本说明](releases/1.3.2.md)为准，历史目标手机前置验证不等于当前集成版本已经完成全部验收。

独立 `gpuPreview` 原型已退役。当前 GPU 材质检查使用 `preview` 的 `hardware=true` 路径，直接复用生产阅读器组件；下文提及原型的内容保留为历史记录。

## 2026-10-26 后续修复（纳入 1.1.3 本地构建）

- 清晰度 100% 在 Compose 与 GPU 两条路径中都保留有效背景，模糊半径归零；GPU 边缘折射可在无 blur 输入时独立工作。折射最大位移 3.2dp，影响带不超过 13dp 或短边 20%，采样留白同时覆盖模糊和折射。（1.1.3 时期的历史值；2026-11-01 起的当前值见下文“共享玻璃边缘”一节。）
- 普通玻璃容器使用连续底色，停止绘制空间变化的局部保护块。底色不透明度为 `floor + (1-floor) × (1-clarity/100)²`，日间 floor 为 8%，夜间为 10%。背景不可用时保留稳定表面。100% 的背景文字仍会透出，不承诺任意叠加内容都具有固定对比度。
- 保留六层散射和两条细线，散射、暗轮廓、窄高光分别增加 10%、15%、20%；所有边缘先于前景绘制，最终 alpha 限定在合法范围。（当前实现已改为两层散射加厚层暗部，见下文。）
- 阅读顶栏两行间距为 6dp。底栏与“更多”中的自动阅读直接启动生产控制器，速度仍在阅读设置调整。
- 普通纵向列表与弹层共用轻微回弹，阻力 0.25、上限 24dp、弹簧刚度 400、阻尼比 1；正文 WebView 不接入。可拖动弹层优先消费位移，后台与离页清零。
- 本轮逐项证据和验证边界见[阅读交互与玻璃质感修复验收记录](archive/reports/reader-polish-2026-10-26.md)。以下版本说明和历史章节保留其形成时的语义。

## 2026-10-30 上下栏底色角色曲线（1.3.0 本地构建）

上下栏不再由调用点决定底色浓度。旧版 `ScreenHeader`、`AppNavigationBar`（底座与选中胶囊）、`ReaderChrome`（顶／底栏）五处传 `.66`（日）／`.78`（夜），材质层再取最大值，于是模糊与折射正常也只剩一块主题白底。

现在底色只由公共策略决定，且 `GlassSurface`／`glassBackground`／`hardwareGlassBackground` 已移除 `minimumTintAlpha` 参数：

| 角色 | 函数 | 0 档 | 60 档（默认） | 100 档 |
| --- | --- | --- | --- | --- |
| 上下栏、栏内小控件、选中胶囊 | `liquidBarOpacity` | 日 .46／夜 .52 | 日 .1408／夜 .1672 | 日 .08／夜 .10 |
| 面板（目录／设置／消息／确认框） | `liquidPanelOpacity` | 1.0 | 日 .31 | 日 .08／夜 .10 |

- 清晰度 0 是最朦胧的一档（模糊半径最大），不等于关闭；关闭仍是不透明稳定表面，GPU 不可用仍是 `.94` 降级底。
- 弹窗不再单独封顶到 80 档：面板与上下栏共用 0–100 语义，100 档同样零模糊（用户 2026-10-30 确认可接受）。
- 数值由 `LiquidGlassPolicyTest.barTintStaysLockedToTheAcceptedSamples` 锁定；要改数值必须重新走界面验收，不能只在测试里放行。

细节、前后对比与残余限制见[修复报告](archive/reports/glass-bars-white-tint-fix-20261030.md)。

## 2026-11-01 共享玻璃边缘（1.3.2 整合版）

用户反馈“只有磨砂、没有玻璃边缘”。本轮不改底色曲线、不改布局与交互，只重做共享材质的边缘：让边界有连续曲面感、可辨认的局部背景弯折，以及沿轮廓转向的受光／背光。

接手本计划执行时，工作区已包含 4.6dp／9.5dp 折射、两层散射及四张背景的未提交改动。实际“修改前”包从该工作区构建，不能把下表历史参数当成本轮截图基线。本轮补充轮廓法线光影、组合采样留白和独立光学对照；原始差异、APK 与验收记录保存在对应验证批次。

| 项目 | 历史实现 | 当前 |
| --- | --- | --- |
| 折射最大位移 | 2.1dp | 4.6dp，并按短边 9% 限幅（`liquidRefractionStrengthDp`）；实际效果由同场景像素与视频验证 |
| 折射影响带 | `min(6dp, 短边 × 12%)` | `min(9.5dp, 短边 × 18%)` |
| 位移曲线 | `weight²`，贴边最陡、向内单调收窄 | `1 - .8t - 1.4t² + 1.2t³`；内沿的值与一阶导数均为零，共享系数传给 AGSL |
| 采样方向 | 向轮廓外侧偏移，夜间斜纹实测出现贴边彩条 | 沿法线向内采样，受控透镜映射留在影响带内；按当前限幅计算最小导数约 .328，防止反向折叠 |
| 轮廓外采样 | 原 shader 未单独屏蔽轮廓外位移 | `d > 0` 时位移权重为零，采样原位置；轮廓上仍有折射 |
| 散射带 | 1 层，3.2→1.8dp | 2 层（.34／.92 权重），3.4→1.9dp |
| 内侧暗部 | 无独立图层 | 新增厚度带，宽 = 散射带 × (1.7→1.45)，透明度随清晰度收薄 |
| 暗轮廓 | .6→.45dp，alpha .065→.04 | .55→.38dp，alpha .048→.03 |
| 受光高光 | 1 条 1→.65dp 线 | 柔光（2.6 倍宽、.42 强度）+ 亮线（1.05→.7dp）两层 |
| 光向 | 按高度／位置渐变 | 固定上方略偏左光向 `(-.2425, -.9701)`；直边用单位外法线，圆角用椭圆法线环形渐变，在切点对齐直边颜色 |

- 采样留白 `liquidMaterialPaddingPx` 改为“模糊半径 × 2 + 最大位移 + 1px”：折射读取的是模糊后的输入，两项外扩必须同时覆盖。关闭折射时只保留模糊留白；清晰度 100 的零模糊分支仍有独立折射输入。
- 底色语义未变：`liquidBarOpacity`（0 档日 .46／夜 .52，60 档日 .1408／夜 .1672，100 档日 .08／夜 .10）与 `liquidPanelOpacity` 原样保留，本轮没有新增任何整栏下限或文字保护色块。
- 边缘绘制仍是 Compose 路径与 Brush，没有新增 GPU 通道。路径／光影按真实轮廓、明暗和清晰度缓存；描边被裁掉的外半宽已计入高光宽度。硬件路径(API 33+)另用 RuntimeShader 弯折背景，API 31–32 只保留模糊与几何光影。任意路径轮廓保留稳定渐变降级，不推算其法线。
- 测试覆盖法线投影连续性、折射曲线的有限值与内沿连续性、小控件限幅及组合采样范围；数值通过不等同于视觉通过。预览新增随正文滚动的固定图案和独立 `refraction` 开关，保留相同边缘光影后再比较折射像素；两者不进入产品 UI 或持久化配置。

## 1.1.2 行为更新

- 玻璃现由独立开关与 0–100% 清晰度控制，清晰度 0% 表示最朦胧，不再承担关闭含义。关闭保留上次清晰度；旧 `ui_glass_transparency_percent` 仅用于迁移及旧版兼容投影，新记录 `ui_glass_appearance_v1` 是事实源。
- 清晰度同时影响底色与模糊半径，100% 的 GPU 路径不使用模糊 effect。当前 GPU 绘制没有接入下文历史描述的局部前景保护，因此不能据旧文档承诺高对比背景上的文字可读性；最高档的文字叠加现象本次保留。
- 两条材质路径复用边缘绘制；当前为两层方向性散射带、内侧厚度暗部、发丝暗轮廓与两层受光高光（历史版本为六层散射带加两条细线）。宽带受面板短边限制，浅/深主题及清晰度采用对应参数。
- 首次读取和迁移过程中，新的用户设置优先于刚加载的旧值；GPU 预览构建调用已随外观模型迁移。

## 统一外观与日夜阅读样式

应用和阅读器共用三个模式：**跟随系统、日间、夜间**。应用模式决定当前使用哪组阅读样式，阅读背景不再反向改变整个应用的明暗模式。

日间、夜间分别保存一组阅读配色、纯色/图片背景、背景图片选择和图片不透明度。修改当前组不会覆盖另一组；字体、字号、排版、进度、笔记等仍由原有配置和数据管理。两组使用各自适配的配色与内置背景，保存时会归一化非法色值、跨组素材和透明度值。

新的偏好键是 `app_appearance_v1`，使用现有偏好表，不新增 Room 表结构。只有新键不存在时才从已保存的旧 ReaderConfig 迁移：默认应用模式为“跟随系统”，把旧阅读样式放入匹配的日间或夜间组，另一组使用默认值。旧外观字段继续保留、同步，供回退版本读取。已有但损坏的新记录不会被重新当作首次迁移并自动覆盖。

实现依据：[外观模型与迁移](../app/src/main/java/com/mirad/reader/core/model/AppAppearance.kt)、[偏好保存与迁移入口](../app/src/main/java/com/mirad/reader/data/repo/SettingsRepository.kt)。

## 阅读场景的显示与分析分层

统一外观作用于全应用；以下 GPU 显示、采样频率和 CPU 显示捕获指标，特指**阅读器及其同窗口控制层**。其他页面保留各自的共享玻璃通路，不套用阅读 GPU 指标。

阅读窗口分为两个原生兄弟层：

- **内容层**：真实 WebView 正文、COVER 旧页动画图、Compose 页眉页脚和系统栏保护。ReaderBackdropHost 将这层记录为原生 RenderNode；内容变化时更新，不把玻璃控件录回背景。
- **控制层**：阅读顶底工具栏、菜单、底部弹层和确认/输入对话框。材质在 GPU 上读取内容 RenderNode，前景文字与图标独立绘制，保持清晰。
- **分析支路**：从内容节点记录一个独立的小 RenderNode，仅用于背景特征分析。任一边不超过 64px，任务开始间隔至少 500ms，最多一个任务在途；GPU 小图的像素读回和统计在后台线程执行。分析结果只保留亮度、颜色等指标，不作为显示图片发布。
- **局部前景保护**：GPU 根据前景覆盖范围绘制保护层，再绘制清晰前景；不会因为文字保护而把整张高透明面板统一加成厚实蒙层。无有效分析时采用保守保护，并在指标更新后平滑调整。

显示内容保持原始分辨率。**零 CPU 显示捕获不等于完全没有 CPU 像素读取**：最多 64px 的分析读回是有意保留的独立支路。内容静止时不持续分析；玻璃为 0%、没有可见消费者、进入后台或省电/简化条件生效时停止相应材质工作与分析。旧尺寸或旧代次结果会丢弃。

分析变化通知来自滚动、分页、正文/样式修改、图片及字体完成等实际内容事件，不把 WebView 的 `onDraw` 当作变化依据。通知合并后至多每 500ms 发送一次；CSS 动画或过渡只在运行期间续期，结束或页面隐藏后停止。观察器不改写正文 DOM，也不改变阅读位置；实时 GPU 显示不受这个分析频率限制。

透明度 0% 是明确的不透明关闭档。高透明度保留薄底色、背景模糊及局部保护；采样和保护算法不是任意背景、任意文字颜色下逐像素对比度的保证。

实现依据：[原生场景与快照](../app/src/main/java/com/mirad/reader/ui/reader/ReaderHardwareScene.kt)、[GPU 材质](../app/src/main/java/com/mirad/reader/ui/common/LiquidGlassMaterial.kt)、[分析生命周期](../app/src/main/java/com/mirad/reader/ui/common/HardwareGlassBackdrop.kt)、[分析尺寸与单任务调度](../app/src/main/java/com/mirad/reader/ui/common/LiquidGlassPolicy.kt)。

## 同窗口交互、COVER 与兼容边界

阅读菜单、弹层和对话框通过 ReaderOverlayHost 显示在阅读 Activity 的控制层中。它负责最上层返回、IME 收起、焦点和语义隔离；模态层出现时，正文与下层控件不应继续接收操作。音量键也经过模态守卫。文档层保持最后一次未被 IME 遮挡的高度，控制层继续使用键盘避让，避免输入弹层压缩正文、引起额外阅读重排。

COVER 在 API 29+ 通过 RenderNode、HardwareRenderer 和 ImageReader 生成独立硬件缓冲，再包装为 HARDWARE Bitmap；显示旧页不做 CPU 像素复制或扫描。旧页仍参与内容层合成。自动翻页等待捕获与章节就绪，取消链与自动阅读控制器保持一致。API 26–28 保留既有软件旧页路径及其交互，不把这一兼容路径计入“GPU 零 CPU 显示捕获”的范围。

| 当前代码路径 | 阅读显示与兼容行为 |
|---|---|
| API 33+、硬件能力可用 | RenderNode 背景、GPU 模糊与局部前景保护；支持的轮廓启用边缘折射 |
| API 31–32、硬件能力可用 | GPU 背景模糊与前景保护，不启用 RuntimeShader 边缘折射 |
| API 29–30 | 阅读材质使用高不透明度简化样式；COVER 硬件快照仍可用 |
| API 26–28 | 保留简化阅读材质与旧 COVER 路径 |
| 硬件不可用、内容节点/坐标未就绪、省电或强制降级 | 使用可读性优先的主题表面；不把未就绪帧当作已启用的玻璃材质 |

没有更改书籍导入、阅读位置、笔记和统计的数据模型。正文测量、系统安全区、长按选词、工具栏点击优先级、自动阅读暂停规则和 WebView 释放仍是原生验收的必要条件。
