## 2 检测方法与执行顺序

| 顺序 | 检测方法 | 主要验证内容 | 证据边界 |
| --- | --- | --- | --- |
| 1 | 源码与契约对照 | 功能入口、回调、取消与释放、数据格式、低版本回退、JS 拼接顺序 | 静态核查，不代替运行结果 |
| 2 | JVM、Lint 与构建 | 分章、解析、设置写入、状态机、搜索导航；三个构建类型 | JVM 不证明 Android 触摸、实际数据库或 GPU 表现 |
| 3 | Chromium 阅读器回归 | 分页、滚动、锚点、标注、自动阅读、内容变化信号、CSP | 不代替设备上的 Android WebView |
| 4 | 真实 Debug 包功能测试 | 从导入到阅读、记录、导出、朗读和退出重开的完整流程 | 必须使用真实业务包和独立测试数据库 |
| 5 | Preview 专项检查 | 玻璃、弹层、COVER、键盘、安全区域、日夜外观与生命周期 | 内存夹具不能证明业务导入、落库和实际 TTS 服务 |
| 6 | 重构前后对照与数据检查 | 同条件操作结果、覆盖安装、持久化、删除与失败恢复 | 同 APK 类型、签名、镜像、样书和设置比较 |
| 7 | 性能、内存与有限随机操作 | 启动、翻页、弹层、退出后的资源回收、崩溃和 ANR | 模拟器数值用于比较与定位，不作为真机帧率承诺 |

前置检查失败时，停止依赖它的用例，其他独立检查可以继续。不能跳过失败项后给出“全部通过”。同一失败先保存证据，再使用相同输入复现一次；必要时在基线包复现，以区分原有问题与本轮回归。

## 3 固定测试对象和环境

### 3.1 源码与 APK

开始前记录分支、HEAD、完整工作区状态、已跟踪文件差异，以及未跟踪源码的路径和 SHA-256。由于重构尚未提交，HEAD 相同不代表测试的是同一份代码。

为本轮生成唯一 `RunId`，证据统一放在 `build/verification/app-qa/<RunId>/`。构建后将候选 Debug、Preview 和未签名 Release APK 复制到该目录的 `apks/`，记录版本、包名、构建类型和 SHA-256；后续安装固定副本，避免测试期间被新构建覆盖。

重构前 Debug 包从基线提交导出完整源码到本轮临时目录后构建，不切换或覆盖当前工作树，不使用只包含部分源码的旧统计快照。基线与候选覆盖安装前比较包名和签名证书；不得把正式 Release 包与 Debug 包混装，再将卸载后的空数据误判为兼容性通过。

### 3.2 两类模拟器分别管理

| 类型 | 用途和限制 |
| --- | --- |
| 业务功能实例 | 新建独占 AVD，运行 `com.mirad.reader` Debug 包，验证真实 Room、导入、进度、书签、笔记和 TTS。测试数据全部由本轮创建。 |
| 玻璃预览实例 | 使用 `tools/glass-preview/Invoke-GlassPreview.ps1` 创建并管理，只安装 `com.mirad.reader.preview`。不在此实例中运行真实业务包。 |

现有预览驱动的 `Install` 明确只接受隔离预览包。不能修改其安装守卫，也不能通过 `Adb` 子命令绕过它安装业务 APK。仓库目前没有完整业务功能验收驱动；执行阶段可在本轮证据目录中准备最小业务实例管理脚本，遵循以下约束，不复制一套产品实现：

- 使用独立的 `ANDROID_USER_HOME`、`ANDROID_EMULATOR_HOME`、`ANDROID_AVD_HOME` 和私有 ADB 服务；记录 AVD 路径、进程 ID、命令行、创建时间、服务端口和设备 serial。
- 预览默认端口为 ADB `5049`、模拟器 `5580/5581`；业务实例可选 `5051`、`5582/5583`，使用前核实空闲。不得停止未知占用进程。现有预览套件按默认端口调用驱动，不能只在创建时换端口却让后续套件使用另一套端口。
- 私有 ADB 启动沿用已有驱动的 USB 隔离和 `ADB_MDNS_AUTO_CONNECT=0` 策略；不使用默认 `5037` 服务。所有设备操作同时指定私有服务端口和已核验归属的 serial，禁止无目标的 `adb install`、`adb shell` 或全局停止服务。
- 后台启动使用隐藏窗口和独立日志，长任务及时返回。只有实例归属核验通过、设备在线且 `sys.boot_completed=1`，才能安装和执行用例。
- 业务实例验证 TTS 时不能禁用模拟器音频；记录 TTS 引擎、语言包、媒体音量和音频输出条件。
- UI 点击坐标从本步骤最新的 UI 树节点 bounds 计算。节点找不到时，滚动后重新读取；不得用旧截图坐标盲点并宣称用例通过。

ADB 的安装、启动和按 serial 定向控制参考 [Android 官方 ADB 文档](https://developer.android.com/tools/adb)。本项目的私有服务及所有权规则优先于文档中的默认服务示例。

本机上一轮使用的 Chromium 缓存为 `build/verification/simplify-and-split/playwright`。确认缓存存在且与锁定的 Playwright 匹配后，可以只在测试进程中设置 `PLAYWRIGHT_BROWSERS_PATH` 复用它；不可把缺少浏览器当作业务测试失败。工具缺失时先按[开发文档](../DEVELOPMENT.md)核对环境，不升级依赖来规避失败。

验收时解析 XML/JSON 报告并检查实际失败、错误、跳过数量，不只看终端 `BUILD SUCCESSFUL`。原有用例不得减少；用例数或套件数变化必须说明原因。Lint 与现有基线逐项比较，避免仅比较总数量而漏掉新增问题。

### 4.2 重点检查清单

- TXT 普通与流式路径：字符偏移、UTF-8 字节区间、前言、分卷、无标题兜底、多字节字符和长行处理一致。
- 设置：400 ms 防抖、并发编辑锁、后台/退出 flush、旧键双写；新记录缺失时迁移，损坏时默认回退，不能重新覆盖迁移。
- 会话：初始化失败不能覆盖进度；搜索取消和跨章回调身份校验保留；退出释放 WebView、音量键、自动阅读和资源句柄。
- TTS 与自动阅读：启动、暂停、跨章、请求替换和通知栏恢复互斥；旧请求不能控制新书或新章节。
- JS：统一文本遍历后的块分隔与选区偏移、CFI/TextQuote、字号变化、延迟资源、裁剪/前插章节、高亮与朗读标记；语义变化信号保持节流。
- 数据与接口：Room schema、持久化模型、Manifest 入口、JS 桥接方法、低版本回退和 R8 保留规则不得意外改变。
- 打包：通过 `tools/browser-checks/reader-source.cjs` 得到测试输入，逐字节比对三个 APK 的 `assets/reader/reader.js`；同时检查没有遗漏或重复打包源码片段。
- 源码量：沿用上一轮统计口径，包含新增测试和工具代码。不得通过跳过新文件、删除断言、压行或移动目录来宣称减量。

## 5 测试夹具

夹具、下载文件和导出结果均放在本轮目录，不使用个人书籍。每个夹具记录来源/生成方法、SHA-256、预期章节及可识别文本片段。

先使用 `tools/make_samples.py <本轮 fixtures 目录>` 生成已有 GBK TXT、无章节 UTF-8 TXT 和带图片 EPUB，再补充下列有明确用途的样本。Python 必须先确认真实解释器可运行，不能把 WindowsApps 占位命令当作成功执行。

| 编号 | 数据 | 用途 |
| --- | --- | --- |
| T1 | UTF-8 有/无 BOM，中文、英文、emoji、前言、分卷和重复词 | 识别、分章、搜索、字符与字节定位 |
| T2 | GB18030/GBK 样书，以及允许手动重新识别编码的副本 | 编码调整和笔记锚点处理 |
| T3 | 无章节、空文件、超长行，以及约 16 MiB 的有效 TXT | 兜底分节、失败提示、大文件与取消恢复 |
| E1 | 图片、封面、目录、相对 CSS/图片路径的 EPUB | 统一/原版排版、资源加载和目录跳转 |
| E2 | 连续短章、很长章节、可识别跨章文本的 EPUB | 连续滚动、章末接章、非活动章选区 |
| X1 | 损坏 EPUB、无效路径、超出当前大小上限的输入 | 有界失败，书架和既有数据不损坏 |
| N1 | 受控 HTTP 文件、HTML 长文、重定向、404 和慢响应 | 网址导入、取消、失败与重试 |
| A1 | 一张自建背景图和可合法使用的测试字体 | 导入、删除、日夜独立记忆和重排 |

大小边界以执行时的常量为准：当前导入单文件上限为 80 MiB，网页正文上限为 8 MiB；EPUB 章节读取也有单独上限。边界测试优先在 JVM 完成，模拟器只做有界的代表用例，避免用无限数据把测试环境耗尽。

HTTP 夹具服务仅监听主机回环地址，通过目标业务模拟器的私有 ADB 反向端口映射访问。服务独占、后台运行并记录进程归属；不创建公开入口。HTTPS 分项需要可信、可控的测试来源；缺少来源时单独标为阻塞，不修改应用网络安全配置来绕过校验。

分享/打开方式测试必须使用文件应用或测试专用 ContentProvider 提供的有效 `content://` URI 和读取授权，不用不可读的伪造 URI 代替完整分享流程。

| F20 | P0 | TTS 从当前位置/章首开始、暂停/继续、上一句/下一句、自动接章 | 朗读内容、当前句高亮与章节一致；旧请求不能驱动新章节，控制项状态正确 |
| F21 | P0 | TTS 与自动阅读相互启动；通知权限允许/拒绝；通知栏恢复与停止 | 二者不同时控制阅读位置；拒绝通知权限不破坏朗读控制链；外部恢复仍执行互斥 |
| F22 | P1 | 阅读后切后台、回前台、退出；查看统计 | 后台时间不当作持续阅读；单书记录及汇总符合实际操作，无重复结算 |
| F23 | P0 | 对已有笔记书签的 T2 重新识别编码/章节 | 正文和目录正确更新；锚点映射或失效提示符合现有规则，其他书籍记录不受影响 |
| F24 | P0 | 删除单书/多书，分别取消和确认；重开并检查记录 | 取消无副作用；确认只删所选测试书及关联数据，其他书的进度、笔记和统计保留 |
| F25 | P0 | 损坏文件、读取失败、离线本地阅读、失败后再导入有效书 | 错误可理解且可继续操作；无 ANR、假书籍或对既有数据的破坏 |

TTS 的“实际出声”和“控制链工作”分别记结果。只有可听确认或有效音频证据才能判定出声通过；没有引擎、离线语音包或有效音频输出时，该分项为阻塞，不能用按钮变化或高亮代替。

## 8 数据持久化与基线对照

### 8.1 同条件对照

在相同镜像、WebView 版本、屏幕、系统字体、样书及设置下，分别记录基线和候选的 F02、F08–F16、F19–F23。比较用户可见结果与状态变化，不用代码内部字段相同替代功能结果。

出现失败时，用相同输入复现基线。基线也失败则记录为既有问题；候选新增失败或结果退步则记录为重构回归。两者都不能从报告中删掉。

### 8.2 保存和恢复

1. 在业务实例创建至少两本书的进度、书签、划线、笔记、分组和日夜设置，记录可读的核对清单。
2. 执行正常返回、HOME 后返回和应用重开，验证即时操作与已保存状态。
3. 关键设置完成提交/flush，进度完成保存后，再强制停止应用、重新启动以及重启模拟器，检查清单逐项恢复。诊断时至少留出大于现有 400 ms/600 ms 防抖窗口的等待，并记录实际时间。
4. 在提交前被直接强杀的短时修改单独记录，与基线对照；不能把尚未承诺落盘的编辑丢失直接判为重构回归。
5. 在基线 Debug 包建立测试数据后，以同签名候选 Debug 包执行保留数据的覆盖安装，再重复检查。记录两个包的实际版本；此前 1.1.3 同版本覆盖安装的证据不能替代本次 1.1.3 到 1.1.4 的升级安装验证。
6. 必要时停止测试应用，按一致快照方式提取测试数据库及其 WAL/SHM，在副本上检查 `quick_check`、`foreign_key_check` 和关键记录。只读取本轮模拟器数据，不修复或改写数据库原件。

UI 读回、数据库副本和 JVM 存储测试分别记录。Preview 的内存 DAO 重建不等于真实进程退出后的持久化。

## 9 稳定性和性能检测

### 9.1 有限随机操作

业务功能通过后，在可丢弃的测试数据上运行 500 个事件，固定 seed、限制包名，约 150 ms 间隔。保存事件日志、crash buffer 和 ANR 信息；不使用忽略崩溃或超时的选项。任务在后台执行，设置有限超时，只停止本轮进程。

```powershell
& $adb -P $businessAdbPort -s $businessSerial shell monkey -p com.mirad.reader -s 20261027 --throttle 150 -v 500
```

Monkey 用于补充发现崩溃和状态组合问题，不能代替前面的功能用例；相同 seed 支持复现事件序列。[Android 官方 Monkey 文档](https://developer.android.com/studio/test/other-testing-tools/monkey)

### 9.2 有界性能对照

基线和候选使用相同构建类型，先预热一次，再各测三次并保留全部结果。分别测冷启动、打开 T3、连续翻页、COVER、连续滚动、快速拖动字号/玻璃滑杆，以及打开关闭弹层。每个场景约 30 秒，记录中位数和波动范围。

```powershell
& $adb -P $businessAdbPort -s $businessSerial shell dumpsys gfxinfo com.mirad.reader reset
# 执行本次指定场景
& $adb -P $businessAdbPort -s $businessSerial shell dumpsys gfxinfo com.mirad.reader framestats
& $adb -P $businessAdbPort -s $businessSerial shell dumpsys meminfo com.mirad.reader
```

记录帧数、卡顿计数、可用的帧时间分位数、PSS、Java/native/graphics 内存与 Activity/View 数量。往返进入退出阅读页十次，回到同一空闲状态取样；持续增长时再采集堆转储和引用链，不能仅凭一次 `meminfo` 判断泄漏。

若出现可复现的卡顿、长主线程任务或持续增长，使用有明确起止的 Perfetto/System Trace；CPU 热点再用可用的 Simpleperf。仅在捕获中实际存在相应轨道/事件时报告 FrameTimeline 或 Compose 重组，不能用普通日志推断每帧重组次数。[Android 官方系统跟踪说明](https://developer.android.com/topic/performance/tracing/on-device)

性能对照的首要失败条件是新增崩溃、ANR、不可操作卡顿或持续资源增长。其他性能差异结合三次波动定位，不凭单次模拟器数值设定真机性能结论。

## 10 证据与通过标准

每个用例至少记录：`case_id`、测试包哈希、镜像/API/WebView、夹具、前置状态、实际步骤、预期与实际结果、状态、证据路径。状态固定为 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`，不得将后两项计为通过。

建议证据目录：

```text
build/verification/app-qa/<RunId>/
  manifest.json          源码、工具、实例归属、端口与 APK 哈希
  apks/                  固定测试包和校验信息
  fixtures/              本轮测试数据
  automated/             JVM、Lint、浏览器和构建输出
  business/              实际业务包的逐用例截图、UI 树、日志和结果
  preview/               各 Preview 套件结果及查看记录
  persistence/           数据核对清单与受控数据库副本
  performance/           三次对照结果、有限随机操作和必要 trace
  results.json           逐用例结果及缺陷
  summary.md             简短结论、问题分级和未覆盖项
```

截图以二进制流保存并验证 PNG，避免旧 PowerShell 文本重定向损坏图片。日志按用例时间和进程关联；有崩溃时先保留现场，不先清日志。后续保存或重新打开的读回结果比操作 toast 更能证明成功。

通过要求：

- 现有自动化用例全部通过，无未解释的减少/跳过，Lint 无新增问题，三个构建类型成功且 APK 内 JS 与测试输入一致。
- 主环境的业务及 Preview 必测用例全部有结果；没有新增功能缺失、数据损坏、定位回退、崩溃或 ANR。
- 覆盖安装、退出重开和已提交数据恢复通过；基线差异逐项说明。
- 兼容性、实际 TTS 出声或其他必测项被阻塞时，只能报告“已完成部分验证，存在未覆盖项”，不能宣称全功能或全平台验收通过。
- 未签名 Release 不能直接安装。未安排受控的测试签名与设备运行时，Release 的结论限于构建、R8/资源/桥接契约检查，不能从 Debug 结果外推为 Release 运行通过。

缺陷按影响报告：P0 为数据丢失/损坏、启动或核心阅读不可用；P1 为主要功能失败或明显回归；P2 为局部布局、非阻断交互或性能问题。每条包含最短复现步骤、实际结果、对应基线结果和证据，不只给结论。

## 11 收尾

预览与业务实例各自由其创建方在 `finally` 中停止。先按已记录私有服务和 serial 请求关闭模拟器，确认进程与端口释放，再清理本轮所有权明确的 AVD 和临时数据目录；不能确认归属或停止失败时保留目录并报告。

停止本轮创建的私有 ADB、夹具服务和采集进程，保留测试报告、截图、日志、固定 APK 与必要数据证据。一次性启动/操作脚本完成后清理；有明确复用价值的测试工具才作为交付物保留，并纳入代码量统计。

最终回复给出覆盖范围、通过/失败/阻塞/未测数量、最高优先级问题、报告路径及实例收尾状态。报告中明确哪些是源码/JVM/浏览器证据，哪些是真实 Android 应用操作，哪些是 Preview 夹具。
