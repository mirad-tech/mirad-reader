# 阅读玻璃与统一外观

本页记录 1.0.17（versionCode 18）的统一外观与阅读 GPU 方案，以及截至 2026-10-24 已取得的证据。本地签名测试包已交付；用户要求尽快收尾，停止横屏键盘等边缘场景的进一步复验。目标手机前置验证不等于最终集成版本已经完成全部验收。

## 统一外观与日夜阅读样式

应用和阅读器共用三个模式：**跟随系统、日间、夜间**。应用模式决定当前使用哪组阅读样式，阅读背景不再反向改变整个应用的明暗模式。

日间、夜间分别保存一组阅读配色、纯色/图片背景、背景图片选择和图片不透明度。修改当前组不会覆盖另一组；字体、字号、排版、进度、笔记等仍由原有配置和数据管理。两组使用各自适配的配色与内置背景，保存时会归一化非法色值、跨组素材和透明度值。

新的偏好键是 `app_appearance_v1`，使用现有偏好表，不新增 Room 表结构。只有新键不存在时才从已保存的旧 ReaderConfig 迁移：默认应用模式为“跟随系统”，把旧阅读样式放入匹配的日间或夜间组，另一组使用默认值。旧外观字段继续保留、同步，供回退版本读取。已有但损坏的新记录不会被重新当作首次迁移并自动覆盖。

实现依据：[外观模型与迁移](../app/src/main/java/com/mirad/reader/core/model/AppAppearance.kt)、[偏好保存与迁移入口](../app/src/main/java/com/mirad/reader/data/repo/SettingsRepository.kt)。

## 阅读场景的显示与分析分层

统一外观作用于全应用；以下 GPU 显示、采样频率和 CPU 显示捕获指标，特指**阅读器及其同窗口控制层**。其他页面保留各自的共享玻璃通路，不套用阅读 GPU 指标。

阅读窗口分为两个原生兄弟层：

- **内容层**：真实 WebView 正文、COVER 旧页动画图、Compose 页眉页脚和系统栏保护。ReaderBackdropHost 将这层记录为原生 RenderNode；内容变化时更新，不把玻璃控件录回背景。
- **控制层**：阅读顶底工具栏、菜单、底部弹层和确认/输入对话框。材质在 GPU 上读取内容 RenderNode，前景文字与图标独立绘制，保持清晰。
- **分析支路**：从内容节点记录一个独立的小 RenderNode，仅用于背景特征分析。任一边不超过 64px，任务开始间隔至少 500ms，最多一个任务在途；GPU 小图的像素读回和统计在后台线程执行。分析结果只保留亮度、颜色等指标，不作为显示图片发布。
- **局部前景保护**：GPU 根据前景覆盖范围绘制保护层，再绘制清晰前景；不会因为文字保护而把整张高透明面板统一加成厚实蒙层。无有效分析时采用保守保护，并在指标更新后平滑调整。

显示内容保持原始分辨率。**零 CPU 显示捕获不等于完全没有 CPU 像素读取**：最多 64px 的分析读回是有意保留的独立支路。内容静止时不持续分析；玻璃为 0%、没有可见消费者、进入后台或省电/简化条件生效时停止相应材质工作与分析。旧尺寸或旧代次结果会丢弃。

分析变化通知来自滚动、分页、正文/样式修改、图片及字体完成等实际内容事件，不把 WebView 的 `onDraw` 当作变化依据。通知合并后至多每 500ms 发送一次；CSS 动画或过渡只在运行期间续期，结束或页面隐藏后停止。观察器不改写正文 DOM，也不改变阅读位置；实时 GPU 显示不受这个分析频率限制。

透明度 0% 是明确的不透明关闭档。高透明度保留薄底色、背景模糊及局部保护；采样和保护算法不是任意背景、任意文字颜色下逐像素对比度的保证。

实现依据：[原生场景与快照](../app/src/main/java/com/mirad/reader/ui/reader/ReaderHardwareScene.kt)、[GPU 材质](../app/src/main/java/com/mirad/reader/ui/common/LiquidGlassMaterial.kt)、[分析生命周期](../app/src/main/java/com/mirad/reader/ui/common/HardwareGlassBackdrop.kt)、[分析尺寸与单任务调度](../app/src/main/java/com/mirad/reader/ui/common/LiquidGlassPolicy.kt)。

## 同窗口交互、COVER 与兼容边界

阅读菜单、弹层和对话框通过 ReaderOverlayHost 显示在阅读 Activity 的控制层中。它负责最上层返回、IME 收起、焦点和语义隔离；模态层出现时，正文与下层控件不应继续接收操作。音量键也经过模态守卫。文档层保持最后一次未被 IME 遮挡的高度，控制层继续使用键盘避让，避免输入弹层压缩正文、引起额外阅读重排。

COVER 在 API 29+ 通过 RenderNode、HardwareRenderer 和 ImageReader 生成独立硬件缓冲，再包装为 HARDWARE Bitmap；显示旧页不做 CPU 像素复制或扫描。旧页仍参与内容层合成。自动翻页等待捕获与章节就绪，取消链与自动阅读控制器保持一致。API 26–28 保留既有软件旧页路径及其交互，不把这一兼容路径计入“GPU 零 CPU 显示捕获”的范围。

| 当前代码路径 | 阅读显示与兼容行为 |
|---|---|
| API 33+、硬件能力可用 | RenderNode 背景、GPU 模糊与局部前景保护；支持的轮廓启用边缘折射 |
| API 31–32、硬件能力可用 | GPU 背景模糊与前景保护，不启用 RuntimeShader 边缘折射 |
| API 29–30 | 阅读材质使用高不透明度简化样式；COVER 硬件快照仍可用 |
| API 26–28 | 保留简化阅读材质与旧 COVER 路径 |
| 硬件不可用、内容节点/坐标未就绪、省电或强制降级 | 使用可读性优先的主题表面；不把未就绪帧当作已启用的玻璃材质 |

没有更改书籍导入、阅读位置、笔记和统计的数据模型。正文测量、系统安全区、长按选词、工具栏点击优先级、自动阅读暂停规则和 WebView 释放仍是原生验收的必要条件。

## 已有证据与尚未完成的验证

**目标手机前置验证已获得用户确认：**“已测试，背景同步正常”。对应记录是 iQOO 12 Pro（设备记录型号 V2329A，SDK 36 / Android 16）的单面板 GPU 探针：

| 记录项 | 已确认内容 |
|---|---|
| 显示刷新率报告 | 约 120Hz |
| 完整记录时长 | 30.001 秒，完整 30 秒标记为 true |
| 显示路径 | hardwareCanvas 与 gpuActive 均为 true |
| CPU 显示捕获 | 0 |
| FrameMetrics 回调记录 | 3598 条，记录中的 dropped callbacks 为 0 |

120Hz 是设备报告的刷新率，FrameMetrics 回调数不是持续渲染帧率证明。这份记录确认的是当时探针的背景同步与硬件路径，不能替代最终集成场景中的多个弹层、IME、COVER、前景保护和生命周期验收；也不能据此宣称持续 120fps、零掉帧或已经通过 Perfetto。
