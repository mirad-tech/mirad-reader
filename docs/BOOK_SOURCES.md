# 书源与离线下载

书架「导入」菜单包含「书源管理」「在线搜书」和原有「网址导入」。书源 URL 指返回阅读类 JSON 规则的链接；网址导入仍处理 TXT/EPUB 直链和单篇网页。

## 使用流程

1. 在书源管理输入 URL，导入一个对象或对象数组。原始链接和各条规则会保存到应用私有目录；重新导入更新规则并保留用户的启用状态。无效条目和不支持的规则分别显示原因，获取失败不覆盖旧规则。
2. 在线搜书查询全部已启用且兼容的源。相同书名、作者归并；作者缺失的结果按来源与书籍地址单独显示。
3. 选择书籍，按完整书名在全部启用源补搜，核对详情并读取目录。仅完整、去重、去卷标题后的目录参与章数排名，默认前五，可展开全部。未核实目录与失败原因单列。
4. 查看目录后下载整本。任务固定规则和目录快照，可暂停、继续、取消和重试。只有全部章节成功并实际加入书架才显示完成。含受限章节的目录可查看，但不能整本下载。
5. 完成后作为 EPUB 在原书架离线阅读。章节顺序与已核实目录一致，支持现有目录、阅读进度、书内搜索及朗读流程。不同站点的分章方式可能不同，章数不代表正文质量。

## 兼容范围

| 能力 | 当前支持 |
| --- | --- |
| 源类型 | 文字小说；保存原始 JSON 未知字段 |
| 导入 | HTTP/HTTPS，单个对象或数组，按 `bookSourceUrl` 识别重复源 |
| 请求 | GET/POST、请求头、字符集、gzip、相对地址、有限重定向 |
| 提取 | 默认 class/id/tag/children 选择器、索引与排除，CSS，XPath 1.0，JSONPath，正则提取/替换 |
| 组合 | `&&`、`||`、`%%`，模板表达式，`@put`/`@get` 与上下文变量 |
| JavaScript | `<js>`、`@js:`、`{{…}}` 中的纯数据运算；受限的变量存取与 Base64 文本帮助方法 |
| 分页 | 目录和正文分页；反序目录、重复链接、分页循环检测 |
| 不支持 | 登录/验证码交互、WebView、外部 `jsLib`、脚本主动网络/文件访问、任意 Java/Android 宿主对象、漫画/音频、自动追更 |

可选 `ruleBookInfo` 缺省时使用搜索结果提供的目录地址。必需的搜索、目录和正文规则缺失时保留源记录并显示不支持原因。这里列出的是适配子集，不是任意阅读书源的兼容保证。

## 实现与恢复

- `BookSourceEngine` 的四个入口为 `search`、`bookInfo`、`toc`、`content`；生产规则经 `SandboxRuleExecutor` 在无应用文件/网络权限的隔离服务执行。宿主只负责 HTTP 和持久化。
- 常规请求共用全局 6、同域 2 的并发预算，排队不消耗网络执行时间；下载一次执行一本书、最多并行取两章。所有实际网络调用可取消。
- 规则计算预算为 3 秒，进程看门狗为 5 秒，IPC 请求预算为 12 秒。通信使用文件描述符传输大页面，避免 Binder 大小上限；异常不会将半页或半章标为完成。
- 源文件位于 `files/book-sources/`，任务清单和章节缓存位于 `files/book-downloads/<UUID>/`。规则、清单和每个章节使用原子替换。取消只清该任务的明确缓存文件。
- 下载完成生成 EPUB3，每章独立 XHTML，远端正文先转为文本并转义，不将站点脚本带入阅读器。沿用 80MB 整本导入上限和 8MB 单章上限。
- 下载任务编号到书籍 ID 的凭据使用已有偏好表，和书籍、章节写入同一事务；不增加 Room 表或迁移。进程在提交后退出时可找回已入库书籍；已删除的书籍不会因旧凭据阻止重新下载。
- API 34+ 使用 UIDT，API 26–33 使用 WorkManager 前台任务。通知与下载页均可控制任务；系统或进程中断后保留断点，用户再次打开应用时恢复可运行任务。强制停止不会被绕过。

新增依赖版本锁定在版本目录，许可与上游声明随 APK 放在 `assets/licenses/`。

## 验证

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --console=plain
```

新增 JVM 测试覆盖受控 HTTP、规则语法与执行限制、书源原子保存、同书归并和完整目录排名、下载断点/取消/重试、并发调度交接、入库凭据及 EPUB 目录回读。

原生闭环使用 `tools/source-checks/` 中自造书源与章节夹具，由本任务独占模拟器通过私有 ADB 连接到本机回环服务。测试结果、截图、日志和候选 APK 哈希保存在 `build/verification/book-sources-20261028/`；设备证据与 JVM/构建结果分别记录，未具备系统镜像的 API 不记作通过。
