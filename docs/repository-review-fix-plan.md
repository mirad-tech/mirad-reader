## 1. P1：修正跨页长段落的阅读锚点

### 问题与位置

`app/src/main/assets/reader/reader.js`：`offsetAtPage()`，约 523–550 行；关联 `offsetAtPos()`、`pageFromOffset()`、`setThemeCssOnly()`、`reportState()`。

`offsetAtPage()` 在段落起点表中找到位置大于等于当前页起点的条目后，直接返回该段落的字符偏移。当当前段落跨越多页且后面还有段落时，这实际上选中了尚未读到的后续段落；精确测量只在查表失败时执行。

审查复现：412×800 视口、24px 字号、1.7 行高，章节含约 2700 字长段落及后续段落。第 3/15 页读取偏移后调用 `gotoOffset()`，跳到第 11/15 页；同一位置把字号 24 调到 26，跳到第 14/18 页。

### 修复要求

1. 保留现有章内文本偏移语义，进度、书签、搜索、划线与朗读继续使用同一份文本模型。
2. 当前页锚点应取实际可见的字符。段落起点表只能作为查找辅助，不能以后一段起点替代当前跨页段落中的位置。优先复用现有 Range 测量和二分逻辑，避免每次操作扫描所有字符。
3. 同时核对分页和滚动模式：页内位置、正文边距与滚动坐标应使用一致的参考系，不把非零安全区域重复计入。
4. 在修改 CSS 或布局前记录锚点，布局后恢复到包含该字符的页面；不重新加载章节，不清除标注或重写正文偏移。
5. 检查滚动模式的进度回报是否因“页号未变”而丢弃最后一次有效位置；如会破坏同一锚点验收，在此范围内修复，并保留合适的节流。

### 验收

- 覆盖单个长段落、长段落后仍有段落、普通多段落，以及带划线/搜索标记的正文。
- 在多个跨页位置执行“当前页 → 读取锚点 → 恢复锚点”，分页模式应回到原页，不跳到后续段落。
- 小字号 → 大字号 → 小字号，验证实际 computed font-size、换行与页数变化，同时确认恢复页仍包含调整前的阅读锚点。
- 覆盖版心限宽、分页/滚动、改字号后立即返回再打开；滚动位置允许有合理的行级误差，不允许跳到下一段或章首。
- 运行实际 `reader.js` 和代表性的生成 HTML/CSS，不以只检查配置值的测试代替排版测试。EPUB 统一排版做回归，保留原书模式不新增排版覆盖。

## 2. P2：为左右两分模式保留菜单入口

### 问题与位置

`app/src/main/java/com/mirad/reader/ui/reader/ReaderScreen.kt`：`session.onTap`，约 383–407 行；关联 `ReaderWebView.kt` 的手势处理。

分页模式的 `TWO` 分支把全部点击分配给前后翻页。`chromeVisible` 初始为 false，返回键退出阅读，长按用于选词，因此保存两分模式后重新进入书籍无法打开目录、设置等工具栏。

### 修复要求

1. 为两分模式提供稳定、可发现的菜单入口，保证仍可从本书设置切回其他点击模式。
2. 默认采用最小交互改动：屏幕中央保留一小块呼出菜单的点击区域，剩余左右区域仍分别用于前后翻页。结合现有点击区域实现确定具体范围，避免新增常驻浮动按钮或大段帮助文案。
3. 不占用长按选词，不改变系统返回行为，不影响三分模式、仅呼出菜单模式及滚动模式现有交互。
4. 菜单呼出点击不能同时触发翻页。

### 验收

- 在本书设置选择左右两分，关闭工具栏、退出书籍、重新打开，仍能呼出菜单并进入设置、目录和进度。
- 验证剩余左/右区域各只执行一次翻页；菜单入口只打开或关闭工具栏。
- 验证长按选词、已有其他点击模式和横竖屏；Android 模拟器不可用时明确标为未做交互验收。

## 3. P2：恢复朗读冷启动期间的待播放请求

### 问题与位置

`app/src/main/java/com/mirad/reader/tts/TtsService.kt`：`onCreate()`、`onInit()`、`onStartCommand()`、`readPlaylist()`、`speakCurrent()`。

首次 `ACTION_PLAY` 到达时，引擎可能尚未完成异步初始化。状态已设为播放中，但 `speakCurrent()` 提前返回；`onInit()` 成功后没有继续这次播放请求。

### 修复要求

1. 明确保留尚未就绪时的最新播放请求及语速、音调；初始化成功后应用参数并开始播放，不要求用户再次点击。
2. 初始化期间若用户暂停、停止或提交了另一份播放列表，就绪回调必须遵从最新意图，不能恢复已取消的请求或旧章节。
3. 引擎初始化失败时结束等待状态，给出现有错误反馈，避免界面永久显示正在播放。
4. 核对前台通知与实际播放状态一致；沿用现有服务和状态总线，不引入新播放架构。

### 验收

- 模拟初始化延迟：播放命令先到，就绪后恰好启动一次正确的句子，使用用户选择的语速和音调。
- 分别验证初始化前暂停、停止、替换播放列表；旧请求不得在就绪后复活。
- 验证初始化失败、引擎已就绪时播放、暂停/继续和正常自动下一章。
- 用真实服务代码及可控引擎替身验证状态顺序；有 Android 语音环境时再验证首次点击能出声。替身测试通过不能表述为真实语音验收通过。

## 4. P2：接通外部打开和分享的文件导入

### 问题与位置

`app/src/main/java/com/mirad/reader/MainActivity.kt`：`onCreate()`，约 33–47 行。`app/src/main/AndroidManifest.xml` 已声明 `ACTION_SEND`、`ACTION_VIEW`，Activity 使用 `singleTask`，但没有消费文件 URI，也没有 `onNewIntent()` 处理。

### 修复要求

1. 使用一条共享处理路径覆盖 `onCreate()` 和 `onNewIntent()`。已有实例收到新 Intent 时，按 Activity 约定更新并处理该 Intent。
2. `ACTION_VIEW` 读取文件 URI，`ACTION_SEND` 读取 `EXTRA_STREAM`；按实际文件分享需要兼容 ClipData。不把仅含 `EXTRA_TEXT` 的普通文字分享当作文件，也不下载网络链接。
3. 复用 `ImportSources` 和 `ImportPipeline`，继续使用现有格式识别、去重、错误提示和导入结果展示。
4. 正确使用来源提供的临时读取授权；不是所有分享 URI 都支持持久授权，申请持久授权失败不能阻止当前导入。缺失或不可读 URI 应有明确反馈。
5. 同一次 Intent 不因界面重组或 Activity 重建而重复入队，同时新的分享事件仍应正常处理；不要用永久记住 URI 的方式屏蔽用户后续主动重试。
6. 不扩大声明支持的格式或 Intent 类型，不增加广泛存储权限。导入结果应能在现有书架/导入提示中被用户看到。

### 验收

- TXT 和 EPUB 分别覆盖冷启动 `ACTION_VIEW` / `ACTION_SEND`、应用已打开时再次接收文件。
- 验证 URI 为空、读取授权不足、重复书籍和普通文本分享，不能崩溃或假报导入成功。
- 验证同一事件不会因重建重复排队，新事件不会被错误忽略。
- 用 Android 模拟器的文件提供方验证 URI 授权和完整入库流程；纯函数测试只能证明 URI 提取/路由，不能代替跨应用验收。
