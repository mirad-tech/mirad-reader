## 3 最小修复要求

两项问题来自同一局部绘制路径，应由一个实现者串行处理，避免多个 agent 竞争修改同一文件。

1. **保护目标必须在最终绘制中成立。** 将实际背景 RGB、玻璃底色、局部保护、高光和文字的合成作为一个完整链路验证。平滑、插值、裁切及叠加后，实际文字承载位置仍需达到普通非禁用文字至少 4.5:1；不能只证明 `peakOpacity` 或某个单元中心达标。
2. **局部效果连续。** 消除矩形裁切和重复叠加产生的可见网格、接缝、条带及闪动。可以调整必要的计算与绘制方式，但保留现有有界采样和共享背景路径，不为此引入整套新框架。
3. **保留高端通透效果。** 普通背景下，100% 继续明显比 60% 更透，且保留本轮修复前 100% 已取得的轻薄感。极端背景只在必要区域增强保护；不通过恢复整块厚蒙层、固定高不透明度或模糊/淡化前景文字来掩盖问题。
4. **不针对夹具硬编码。** 不能只移动采样点、修改测试文字位置、增加单元数量、调整一个梯度常量或删除混色场景就宣称完成。验收覆盖单元内部与边界、背景块平移及多个真实页面，最终依据是可复验的渲染结果。
5. **保持更新与生命周期正确。** 保护需要增强时及时生效，释放可以平滑；拖动与背景变化后稳定收敛，不回写用户百分比，不新增空闲采样或绘制循环。0%、后台、关闭和降级路径继续及时释放资源。
