- 主要路径：默认 `windowedScroll=false` 下的原地滚动换章，包括前进和后退。保留原地换章体验，不将正常 EPUB 换章全部改为整页重载。

## 2. 修复设计

### 2.1 同步原生章节标题

定位：`app/src/main/java/com/mirad/reader/reader/ReaderSession.kt`，`onJsChapterChanged()`，编写时约第 161 行。

**问题场景：** A 章滚动进入 B 章后，状态只更新章号、页码和偏移，`chapterTitle` 仍是 A 章。工具栏、朗读标题以及此后新增书签的持久化标题因此错误。

实施要求：

1. 校验目标章号并取得目标章节后，在同一次 `_state.update` 中更新 `chapterIndex`、`chapterTitle`、`page` 和 `offset`。
2. 保持现有进度、标注、书签状态刷新的顺序；后续 JS 状态回报继续填充实际位置，不因修复标题触发 `loadUrl`。
3. 章节标题来源使用与 `gotoChapter()` 一致的章节元数据；非法章号保持现有拒绝行为。
4. 不批量修改既有书签标题；本次保证新创建书签及当前界面使用正确标题。

### 2.2 同步 EPUB 章节样式与属性

定位：`app/src/main/assets/reader/reader.js`，`swapInNextChapter()`，编写时约第 986–995 行；必要时调整本地章节 HTML 的资源标记处。

**问题场景：** 仅替换正文和 `<base>`，使目标章的 `<link rel="stylesheet">`、`<style>`、`body class/style` 丢失，上一章样式继续污染下一章。“保留原书样式”受影响最明显。

实施要求：

1. 在修改活动文档之前，解析并验证目标正文及章节资源，准备好新章节样式节点和原书属性。
2. 明确区分应用注入样式与书籍样式。应用的阅读器脚本、结构 CSS、当前主题样式、背景层和桥接状态必须保留；只移除上一章拥有的书籍样式。需要增加标记时，仅用于明确资源归属，不引入新的配置项。
3. 按目标文档顺序替换书籍样式表和内联样式，并替换原书的 `html/body` class、style、lang、dir 等表现属性；目标章没有的旧属性应移除。原书属性更新后再执行阅读器布局，避免覆盖布局引擎刚写入的运行时样式。
4. 根据目标章节的有效 base 解析样式表及内联 CSS 相对资源。更新、移除旧 base 时保证目标章资源指向与完整加载该章一致，继续经过现有本地资源拦截和外部请求限制。
5. 不执行从 EPUB 章节复制来的脚本或事件处理属性，不复制应用脚本造成重复初始化。同步策略不能新增脚本执行能力。
6. 样式表完成加载或明确失败后，调用同一套保持锚点的重排逻辑；不能假设两次 `requestAnimationFrame` 等同于资源就绪。
7. 保留现有解析/替换失败时完整加载目标章的恢复路径，避免留下半替换文档。异步回调必须绑定当前换章代次，旧章节回调不得覆盖新状态。

### 2.3 重新监听动态资源并保持位置

定位：`app/src/main/assets/reader/reader.js`，`swapInNextChapter()`、`watchResources()`，编写时换章布局约第 1009–1012 行。

**问题场景：** 初始文档图片有加载监听，换入的新图片没有。未指定尺寸的插图随后展开，页数与文字位置缓存仍停留在旧布局；向前换章、向后回章末及后续跳转均可能受影响。

实施要求：

1. 将资源监听整理为可在每次正文替换后调用的逻辑；监听当前章图片 `load/error`，并处理注册时已经完成加载的缓存图片。
2. 与章节样式、字体加载完成的布局更新复用同一重排入口，合并同一帧内多个资源事件，避免重复全量计算。
3. 每次切章取消旧监听或使其代次失效；在加载失败、图片不可解码和快速连续换章时，不允许旧回调改变当前章节、页数或滚动位置。
4. 重排前保存有效章内字符锚点，重排后重新测量位置和页数，再恢复锚点并报告状态。
5. 前进到下一章保持章首；后退到上一章时，在用户尚未继续操作前保持末尾位置，图片稍后展开仍应到达新末尾。用户开始滚动、搜索、朗读跟随或主动跳转后，以用户当前锚点为准，取消待保持的章末意图。
6. 不使用固定延时等待图片，不无限等待损坏或不返回的资源，也不因重排清空标注、搜索和朗读高亮。

## 3. 验证与验收用例

实现前先用最小样例复现问题；实现后重新运行相同用例。优先复用现有测试方式，不为这次修复搭建无关框架。

| 场景 | 验收要求 |
|---|---|
| TXT A→B→A 滚动换章 | 工具栏与当前章一致；新书签的章号和标题一致；朗读标题正确；正常换章不整页刷新 |
| 非法章号及重复通知 | 不越界、不误改标题、不重复触发导航 |
| EPUB 相邻章使用不同 CSS 文件和 body class | 滚动进入目标章与直接打开目标章的关键计算样式一致，旧样式不残留 |
| EPUB 内联样式、相对背景图片/字体、不同 base | 资源仍解析到目标章节路径，应用主题及本地资源限制不受影响 |
| 目标章没有旧章的 class/style/base | 旧属性清除，不继承上一章特殊样式 |
| 统一排版与保留原书两种模式 | 各自保持已有排版约定，切章后字号、主题和正文显示正确 |
| 未指定尺寸的延迟图片 | 图片完成后页数、字符定位及进度重新测量；没有跳到其他段落 |
| 缓存图片与加载失败图片 | 不漏掉重排，不一直等待或显示空白 |
| 后退章末，随后图片展开 | 未操作时停在最终章末；用户已移动时不被拉回章末 |
| 快速 A→B→C，A/B 的资源稍后完成 | 旧回调不污染 C 的布局、标题或定位 |
| 有笔记、搜索标记或朗读高亮时换章/重排 | 标注属于正确章节，资源重排不意外清除高亮 |
| 分页模式及 `windowedScroll=true` 的已有路径 | 不因共享资源监听改动发生回归，不改变窗口模式默认关闭状态 |

最低验证层次：

1. 运行相关 Kotlin/JVM 回归测试和项目现有单元测试。
2. 使用真实 `reader.js` 和实际章节 HTML 做 DOM/浏览器测试，模拟图片与样式表延迟、失败及缓存命中；断言计算样式、章号、页数及位置，不只检查字符串。
3. 在 Android 模拟器验证真实 WebView 的 TXT/EPUB 前后换章、标题、书签和资源加载后的位置，记录场景及结果。仅操作明确选中的模拟器，不操作用户手机。
4. 运行 `:app:assembleDebug`、`:app:assembleRelease` 及适用 lint，检查输出、退出码和错误数量。构建通过不能代替 WebView 行为验证。
5. 若某个验证环境不可用，记录缺失环境和未验证场景，不将静态检查描述成运行通过。
