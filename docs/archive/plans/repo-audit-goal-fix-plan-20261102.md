### RDR-01 · EPUB 同源资产脚本越过 CSP 信任边界 · P2

- 入口：`app/src/main/java/com/mirad/reader/reader/ReaderResourceProvider.kt:134`，以及 `ChapterHtmlBuilder`、`ReaderWebView`、现有 CSP 测试。
- 反例：EPUB 正文含 `<script src="proof.js"></script>`，同包脚本经 `/book/<id>/asset/...` 提供。生产 HTML/CSP 在 Chromium 中允许脚本执行并调用桥接替身；内联脚本仍被拦截。
- 最小方向：把脚本执行授权限定到可信阅读器资源，明确区分应用脚本和不可信书内资产；保持 CSS、图片、字体、fragment fetch。不要通过关闭整个 WebView JavaScript 破坏阅读器。
- 验收：书内同源脚本、内联脚本、事件属性和 iframe 的负例不能执行或触发桥接；可信 reader.js 正常初始化，分页、补章、图片及字体正例通过。覆盖首次整章、原书样式和窗口补章。生产生成的 HTML/CSP 必须进入实验，不手抄策略。
- 最低证据：生产配置/HTML 回归 + Chromium 安全边界正负例 + 受影响阅读原生组件 smoke。Android 桥接替身与实际 WebView 验证分开标记。
- 测试维护：原 `csp.cjs` 把任意虚拟源脚本可执行当正例，应替换为“可信阅读器可执行、书内资产不可执行”的契约检查；不能只删除失败断言。

### DATA-01 · 合法 UTF-8 被弱 UTF-16 猜测抢占 · P2

- 入口：`core/text/TextCodec.kt:71`、`StreamingTxtProcessor.kt`，路径前缀为 `app/src/main/java/com/mirad/reader/`。

- 最低证据：生产解码器与流式处理器 JVM 回归，使用合成文件，不只检查编码名称。

### DATA-02 · 采样指纹相同被当作全文相同 · P2

- 入口：`data/imports/FileFingerprint.kt:24–57`、`ImportPipeline.kt:99–158`、重复候选查询。
- 反例：两个同名同长的 1 MiB 文件，仅第 200000 字节不同，生产指纹相同而满足 SKIPPED 条件。不是 SHA-256 碰撞。
